Five takeaways for OSS supply-chain hygiene

1. Solo-maintainership is a structural risk.

A project with one trusted contact is a single point of failure for both burnout and trust escalation.

2. Review build-system changes with the same care as code changes.

The xz payload was hidden in build-to-host.m4 and test fixtures — surfaces that often escape review.

3. Behavioral anomaly detection works.

A 500 ms SSH latency anomaly noticed by a careful engineer was the entire detection signal.

4. Reproducible builds expose tampering.

Build outputs that differ between the upstream tarball and the git tag are an immediate flag for investigation.

5. Sandbox untrusted contributors.

Long-tail commit access should require independent review of build-system + binary-asset changes.
